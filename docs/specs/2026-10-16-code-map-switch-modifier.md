## 1. 要解什么问题

用户原话：**「我拿着既不知道如何启用它，也不知道如何为我的老项目开启，这是严重问题。」**

代码地图的规则已进 main，但**没有开关**。实测三处缺口：

| 缺口 | 实测证据 | 后果 |
|---|---|---|
| **启用词未注册** | `apply-to-project.md` §十 只有 `adr` / `doc-lifecycle` / `issue-status`；§六 附加描述表列明「不认识的描述 → **当场问用户**，不猜」 | 说「启用代码地图」会被当成不认识，agent 不敢执行 |
| **没人要求去写入口** | `SKILL.md` 三处挂点只说「查图」；四要素只写在 `references/code-map.md` §三 | agent 走到这步发现没命令可用，只能猜或跳过 |
| **老仓零动作** | `taoxi_system` 的 `AGENTS.md` 实测无 codemap 相关内容 | 规则生效了，落地动作无人做 |

**根因（如实记）**：我把「机制」与「开关」当成同一件事。细则写了四要素，但没接上触发它的人，也没注册启用词。

## 2. 目标与非目标

### 2.1 交付目标

1. 注册稳定修饰词 **`code-map`**，与既有三个同形（§十 八项字段齐全）。
2. 主文件挂点补一句：**入口未写就先补四要素**——让老仓不需要任何人开口。
3. §六 附加描述表加一行，认「启用代码地图 / 加上 code-map」等说法变体。
4. 逃生口写明：项目写「本仓不适用代码地图」即关闭。

### 2.2 明确不做

1. 不新增可执行资产（不跑 `codemap setup`、不写 Hook / MCP / daemon）。
2. 不改既有三处挂点的语义（只在总则那处加半句）。
3. **不主动去改任何采用仓的 `AGENTS.md`**——写给采用仓自己执行，本 spec 只动中央。

## 3. 机制清单

| # | 机制 | 解决什么 / 没有它会怎样 |
|---|---|---|
| 1 | **`code-map` 修饰词**（§十 登记表 + §六 附加描述表 + `SKILL.md` 参考表行） | 给「启用」一个可说的词 / 没有它：用户说不出启用词，agent 撞见不认识就停下问 |
| 2 | **入口缺失自动补**（主文件挂点加半句） | 老仓不需人工提示即被补上四要素 / 没有它：每仓都要人开口，老仓永远停在「规矩要查图、但没命令」 |
| 3 | **逃生口**（「本仓不适用代码地图」） | 小仓 / 文档仓能退出 / 没有它：小项目白付扫描成本 |

### 4.2 `references/apply-to-project.md`

新增 §十 登记表（八项字段，照既有三张的形状），关键字段：

| 字段 | 内容 |
|---|---|
| 修饰词 | `code-map` |
| 语义变体 | 「同时启用代码地图」「加上 code-map」「接入代码地图」 |
| 项目入口 | `AGENTS.md` 的「代码地图」节（§三 四要素的实例化） |
| 项目资产 | **无新增可执行资产**——安装方式 C，二进制在电脑里；项目不装、不跑 `setup` |
| 执行时点 | 采用时写入口；走到「查图」动作而入口缺失时补写 |
| 验收方式 | dogfood：临时假仓验证默认不写入、采用后写四要素、重复采用不重复写、写「本仓不适用」后不再提示 |
| 幂等规则 | 入口节已存在 → 只校验形制，不重复追加 |
| 旧物处置 | 项目已有同类工具或制度 → 只报告差异并指向项目那份，不新建第二份 |

§六 附加描述表加一行（与既有三行同形，**按语义判定、不按字面匹配**）：

```text
| `code-map` / 「同时启用代码地图」「接入代码地图」等**说法变体** | **按语义判定**，不按字面匹配；执行 §三（四要素）+ §十 登记表 |
```

**§六 的「已注册修饰词清单」四行 → 五行**（加 `code-map`），否则契约两侧对不上、`check-docs.sh` 判红。

### 4.3 `references/code-map.md`

§三 补一句：**入口未写时，照本节补写，别停在「没命令可用」**。

## 5. 验收

1. `scripts/check-docs.sh` 九项全绿（含采用契约四项判据）。
2. 正文字数 ≤ 5,000，**余量 ≥ 8**（实测目标 8）。
3. 警示符 ≤ 3。
4. **契约两侧一一对应**：§十 四张登记表 ↔ `SKILL.md` 参考表四行 ↔ §六 清单五项。
5. dogfood（临时假仓）：
   - 默认不启用时**不写**四要素；
   - 说「同时启用 code-map」后，项目 `AGENTS.md` 出现四要素；
   - 重复采用不重复追加；
   - 写「本仓不适用代码地图」后不再提示；
   - **老仓场景**：入口缺失而我方走到「查图」动作时，补写而非跳过。
6. §六 附加描述表五行齐全，且「不认识的描述」那行仍在。

1. 修饰词取 `code-map`（连字符），与 `doc-lifecycle` 同形，不用 `codemap`——后者是工具名，与制度名区分。
2. 登记表插在 §十 既有三张之后，按加入时间排。

4. R25 记：为什么要开关（缺口的来龙去脉）、为什么默认开、余量 11 → 8 的代价。
5. **本 spec 不碰任何采用仓**；采用仓的入口由它们自己按 §十 执行。
