## 1. 要解什么问题

用户要的不是「加一份代码地图文档」，而是**代码地图成为流程的一部分**：agent 在用地图的那个动作上就该想到它，而不是被提醒「这里有一份文档」。

| **织进去**（本 spec） | **109 字符** | 总则一句 + 三处挂点，长在已有动作上 |

**编织省 103 字符，且不新增章节。** 这是本 spec 的核心设计选择。

## 2. 设计：四类挂点，零新章节

代码地图不成为一节，而是四个小句，每个都长在**本来就存在的动作**上。

**四处挂点的确切文字**（照此实施；字符为实测增量，非描述）：

| # | 挂在哪 | 加什么（完整文字） | 字符 |
|---|---|---|---|
| 1 | **主线总则**（九步列表之前，独立成段） | `**动笔前先看代码地图**：改哪、谁受影响，先查图；不可用如实报、回落源码搜索。` | **+43** |
| 2 | **第 3 步**（句尾加半句） | `3. **用户点头之后**才出 spec —— 硬关口：需求没确认就不动 spec 文件；改动面先查图再落笔` | **+10** |
| 3 | **闸·不审档**（表格单元格内插） | `| 不审 | 无；agent 自己拿 diff 对 spec 改动面过一遍（受影响者用地图查），范围外变更停下报告 | 0 |` | **+10** |
| 4 | **参考表**（`done-criteria.md` 行后插） | `| `references/code-map.md` | 查图、判不可用或版本不达标时 |` | **+46** |
| | | **合计** | **+109** |

**为什么是这四处**（不是随便选的）：

- **总则**——九步共同的前提，地图是「动笔前」的事，不是某一步的事；
- **第 3 步**——spec 要写改动面，这是改动面第一次需要证据的地方；
- **闸的「不审」档**——那是 agent 唯一自己拿 diff 对账的档位，正是地图「谁受影响」最能帮上忙的时刻；
- **参考表**——细则的入口，与既有 `gate-details.md` / `worktree-lock.md` 同形。

### 2.1 不挂在哪，为什么

| 步 | 为什么不挂 |
|---|---|
| 第 1、2 步 | 需求还没成形，此时查图先于需求，是浪费 |
| 第 7、8 步 | 实施期查图有价值，但**同一套动作已在总则覆盖**；重复挂会稀释 |
| 新开一节 | 正是用户点名不要的「孤零零一个单元」 |

## 3. 新建 `references/code-map.md`

正文只留动作，细则全部在此。内容：

1. **安装方式 C**：二进制装在电脑里（`brew tap JordanCoin/tap && brew install codemap`，`ast-grep` 随 formula 自动带上）；**项目里不装、不跑 `setup`**。一手 README（`codemap@1fae668` §Setup）列明 `setup` 会写五处：

| 产物 | 内容 |
|---|---|
| `.codemap/config.json` | 自动探测的语言过滤 |
| `.claude/settings.local.json` | 合并 hooks |
| `.codex/hooks.json` | 合并 hooks |
| `.mcp.json` | 配置 MCP |
| `.codex/config.toml` | 配置 MCP |

**措辞说明**：README 原文是「hooks start and read daemon state at session start」——即 **hooks 在会话开始时读取 daemon 状态**；常驻后台 daemon 另由 `codemap watch start` 启动。原稿写成「`setup` 并拉常驻 daemon」是外推，已按原文改正。无论哪种，都属可执行资产，须另行授权。
2. **项目入口四要素**：工具名 + 命令 + 扫描范围 + **声明的版本基线**。写进项目自己的 `AGENTS.md`。
3. **版本基线判定**：低于声明基线 → 按「分析不完整」处理，如实报告。
4. **覆盖率怎么读**：`complete` / `partial` / `unavailable` 三档，以及 `authoritative` / `mixed` / `fallback` / `timeout` / `unavailable` / `failed` 来源状态；超时返回的是**带来源的空结果**，不是空图。
5. **降级报告形状**：缺工具 / 版本旧 / 语言不支持 / 分析不全时，如实报「本仓库代码地图不可用 / 不完整」并回落源码搜索，**不得报成「检查通过」**。
6. **关闭句**：项目 `AGENTS.md` 写「本仓不适用代码地图」即关闭。
7. **已知边界（诚实标）**：静态 import 之外的关系（事件、数据库约定、运行时注入、跨服务调用）不在图里；地图不替代测试与审核。
   - **「是否落盘 / 是否重扫」本 spec 未取证，不做断言**。原稿写的「它不是索引——不落盘、每次重扫」在一手 README 里**找不到对应句**，属外推，已删。README 能佐证的相关事实只有两条：`watch` 是「background daemon for live graph state」（图可常驻内存）、项目级状态落在 `.codemap/`。**收益形态留待用户实测后再写。**
8. **本仓提示**：spec-flow 本身是 markdown 为主的仓，地图增量接近零；别把第一张图花在这里。

### 4.1 必须同时改 `scripts/check-docs.sh`

这是本 spec **唯一的机制改动**，理由要说清：

现行脚本对三行做**逐行字面校验**，要求每行都含「默认关闭」与「声明已采用」（`check-docs.sh` 采用契约一节）。把共通句提到表上方后，三行不再字面含这两串，脚本会判红。

**改法**：把校验从「逐行必须含」改为「三行所在区域含一次」，语义不变——规则仍然是「选修备忘录必须有默认关闭与读取条件」，只是不再要求逐行复述。

**为什么这个改法安全**：检查的目的是「防止某个选修备忘录被漏写读取条件」。区域校验同样能拦：少写就是区域里没有。**逐行校验拦的是「重复」，不是「遗漏」。**

**脚本必须同时看清三处判据（轻审发现 #4，原稿漏了后两处）**：

| 判据位置 | 现在认什么 | 去重后必须改成 |
|---|---|---|
| `:186` | 行内含「选修」才认作选修行 | 行内含「选修 `adr`」等仍成立——**保留**；但要防「三行都因缺「选修」二字而漏认」 |
| `:174` / `:193` | 行内「采用走 `x`」建立 `rows_to_mod` ↔ §十 登记表的映射 | 文字改成「采用走各行标注的修饰词」后**行内不再有「采用走 \`x\`」**——必须改为从修饰词反查，否则 §十 三张登记表会被判「SKILL.md 没登记」 |
| `:218` | 有「采用口径」区块的文件必须在参考表有选修行 | 同上——映射断了会误判红 |

**这三处是同一个根因**：行内承载了「读取条件」与「修饰词映射」两件事，去重只该卸掉前者。**实施时三处一起改，并跑 §7.8 的反例。**

**实测省下 39 字符**（含新增共通说明 63 字符；此前 spec 草稿写的「56」是错的，以实测为准）。

## 8. 机制清单

| # | 机制 | 解决什么 / 没有它会怎样 |
|---|---|---|
| 1 | **编织式挂点**（总则 + 三小句） | 地图成为流程的一部分而非独立文档 / 没有它：正文多一节，读起来仍是一份「文档」 |
| 2 | `references/code-map.md` | 装法、基线、覆盖率、降级形状 / 没有它：细节挤正文，塞不下 |
| 3 | 参考表区域化校验 | 去重不削弱契约 / 没有它：要么重复三遍，要么漏检 |
| 4 | 项目入口四要素 | 项目声明本仓怎么查 / 没有它：agent 不知道敲什么命令 |
| 5 | 「本仓不适用代码地图」关闭句 | 小仓 / 文档仓退出 / 没有它：小项目白付扫描成本 |
| 6 | 版本基线 + 降级报告 | 版本不一致时不会骗人对账 / 没有它：旧版结果被当成查全 |
| 7 | 覆盖率读数（三档 + 六种来源状态） | 让「分析不全」可判 / 没有它：partial 被当 complete 用 |
| 8 | 安装方式 C（装电脑、项目不装） | 不把可执行资产带进采用项目 / 没有它：每个仓被写 5 处配置 + hook |
