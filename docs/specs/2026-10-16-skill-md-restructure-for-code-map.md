## 1. 背景与现状

### 1.1 要解决的问题

`SKILL.md` 正文已顶到自设预算，**新规则无处可放**。

实测（`origin/main@b66e9ad`，`scripts/check-docs.sh`）：

```text
[绿] 正文字数 4,982 / 预算 5,000
[绿] 正文警示符（⚠️ + ⛔）3 / 上限 3
```

余量 **18 字符**。

**关于 5,000 这个数**：它是**字符**预算（`check-docs.sh:6` 的 `BUDGET_CHARS=5000`），不是截断线本身。R10 记的截断线是**会话压缩后每个技能只重挂前 5,000 token**；定预算时特意「离截断线留约 700 token」，所以约 4,300 token ≈ 5,000 字符。超预算的后果是**离截断线越来越近**，不是当场被截。结论不变：往下加规则不能靠上调预算，只能先腾地方。

本次起因是打算把「代码地图」作为主流程一环写进正文（该规则见 issue #85，**尚未批准、尚无分支**）。其核心句约需 400 字符常驻——**必须先腾出等量空间**，否则要么爆预算，要么把它挤进会被截的后段。

### 4.4 阈值下调的裁决（2026-10-16）

实施时实测只有 177 字符余量，未达 spec 原定 ≥400。摆卡后用户选择「按 177 交付，门槛降到 177」：

- **理由**：代码地图进正文的形态是**一句硬判据**（开工前查图 + 缺工具如实报不可用），不是长段落；命令、版本基线、降级报告的形状全进 `references/code-map.md`，不占常驻预算。177 对该形态够用。
- **代价（如实记）**：常驻层只能放最核心的两句；下一份要进正文的规则仍需另行腾地方。
- **未选的路**：压参考表里三行选修说明（合计 325 字符）可凑足 400，但那三行是审核方点名确认的完整性内容，且压后新选修备忘录无处可放 —— 不值当。

### 三类例外的枚举必须留正文（不能外移）

`SKILL.md:34`（卡片总表·例外卡行）被 §2.2 冻结、**且该行写着「属三类例外之一」**。若三类例外的枚举只存在于 `done-criteria.md`，冻结行会引用一个正文里查不到的定义。所以：

- **三类例外的枚举（「真实时间 / 合规要求 / 必要的持续负载测试」）留在正文**，用一句压紧；
