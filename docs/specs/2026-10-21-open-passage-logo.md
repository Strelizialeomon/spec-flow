## 设计约束

- 独立符号直接沿用附件的 `plane` 路径、两次 `<use>`、`rotate(180 80 80)` 和 `viewBox="0 0 160 160"`，不重描、不变形、不新增元素。
- 主红为 `#E5232E`；透明背景；不要黑色、描边、渐变、阴影、立体渲染或内部翻面。
- 白色单色变体使用同一路径与变换，填充 `#FFFFFF`，保留为备用变体，不作为深色模式默认稿。
- 锁定稿固定“符号在左、字标在右”：符号沿用独立符号；字标为 `spec-flow`，使用 Inter SemiBold（SIL OFL 1.1）转曲，不保留 `<text>`、字体引用或外部资源。
- 浅底锁定稿字标 `#1F2328`，深底锁定稿字标 `#FFFFFF`；两者主红与符号几何完全相同。
- 锁定稿画布与间距以确认附件为准，`viewBox="0 0 386.03 160"`；不新增字标装饰、标识语或第二行文字。
- 锁定稿比例采用黄金比：字标 ascender 高 30.47，符号与字标间距为 `30.47 × φ ≈ 49.3`；符号可视高 132 ≈ `30.47 × φ³`（129.1，实际高约 2.3%）。实施不得用随手留白替换这组关系。
- 两份 README 顶部改用 `<picture>`：深色模式引用深底锁定稿，浅色模式引用浅底锁定稿；宽 480px，替代文字仍为 `spec-flow`。锁定稿已含项目名，删除重复的一级标题 `# spec-flow`；正文与节标记不变。
- 保留旧 spec、旧附件与旧来源图；旧白色变体内容留在 git 历史与旧 spec 中，`spec-flow-white.svg` 作为正式资源随新几何更新；不删除、不改写历史。

## 体量评估与结构选择

本次只有一个完整可验收成果：空白通路正式替换（符号、白色变体、两版锁定稿、PNG、来源记录）与双语 README 展示。导出、来源记录和双语展示是同一成果的配套部分，普通核对、导出、测试与提 PR 不算多个实施阶段；没有独立部署、迁移或长期观察阶段。

推荐不拆：保留 1 份执行 spec 和 1 张执行 issue，同批更新资源与展示，避免中途只换符号却继续显示旧的宽 SF。

可选拆法：S01 负责正式符号 / 白色变体 / PNG 与 manifest，S02 负责两版锁定稿和双语 README 展示；另需 1 份总纲、2 份执行 spec、2 张执行 issue 与 1 张仅跟踪父 issue。S02 依赖 S01 的符号几何，且展示无法在正式资源之前独立发布；拆开只增加协调成本。

用户在结构卡选择“不拆（推荐）”：按 1 份执行 spec 和 1 张执行 issue 交付；符号、白色变体、两版锁定稿、manifest 与双语 README 同批完成，不新增多阶段安排。可选拆法仅保留为比较记录。
