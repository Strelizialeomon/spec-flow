# 代码地图：怎么用、什么时候不灵

> 本文件是主文件〈动笔前先看代码地图〉那句的细则：**动作在正文，怎么落地在这里。**
> 主文件〈项目体例与参考〉把它列为必读层之一（与 `split-large-spec.md` 第 1~6 节同）。
> 依据：`rationale.md` R24。

- 2026-10-16 按 #90 spec 立规（实现见 PR #91）。**试用性质**——用户在一个真实业务项目上验过后再定去留。

## 一、它做什么，不做什么

**做什么**：给定一个仓，回答「改哪、谁受影响、入口在哪」——结构视图、依赖流向、某文件的导入方、按实际 diff 算受影响范围。

**不做什么**（必须知道，否则会误信）：

- **不替代测试与审核**。地图说「没有别的调用方」，不等于改动安全。
- **看不到静态 import 之外的关系**：事件、数据库约定、运行时注入、跨服务调用、反射与动态加载都不在图里。
- **「没发现依赖」≠「没有依赖」**——要区分「查过、确实没有」和「分析没覆盖到」。工具会给出覆盖率状态（见 §四），**依它判断，别自己推断**。
- **不是索引，本 spec 未取证它的缓存行为**。一手 README 能佐证的是：`watch` 是「background daemon for live graph state」（可常驻），项目级状态落在 `.codemap/`。**「是否落盘、是否每次重扫」未取证，不做断言。**

## 二、安装：装在电脑里，不装进项目

推荐 `codemap`。装法（Homebrew，`ast-grep` 随 formula 自动带上）：

```bash
brew tap JordanCoin/tap && brew install codemap
```

**项目里不装、不跑 `codemap setup`。** 一手 README 列明 `setup` 会写五处：

| 产物 | 内容 |
|---|---|
| `.codemap/config.json` | 自动探测的语言过滤 |
| `.claude/settings.local.json` | 合并 hooks |
| `.codex/hooks.json` | 合并 hooks |
| `.mcp.json` | 配置 MCP |
| `.codex/config.toml` | 配置 MCP |

并且 README 原文写明「hooks start and **read daemon state** at session start」——hooks 在会话开始时读取 daemon 状态；常驻后台 daemon 另由 `codemap watch start` 启动。**无论哪种都属可执行资产**：脚本 / Hook / daemon 不因一份备忘录被采用就自动创建，要用须先过〈可执行资产升级闸〉。

**代价如实说**：项目不装 = 换机器、新同事入职都要手动装一次；没装的机器上命令直接失败（这是好事，见 §五）。

**本仓提示**：spec-flow 本身是 markdown 为主的仓，地图增量接近零。**别把第一张图花在这里。**

## 三、项目入口四要素

采用的项目在自己的 `AGENTS.md` 写清这四项（缺一项 agent 就不知道敲什么）：

1. **工具名**——本项目用哪个地图工具；
2. **命令**——查结构 / 查依赖 / 查导入方 / 查受影响范围各是哪条；
3. **扫描范围**——限定哪些目录、排除哪些；
4. **声明的版本基线**——本仓验过的版本号。

示例（`codemap`）：

```text
本仓代码地图：codemap v4.6.0（基线）
- 结构：codemap .
- 依赖：codemap --deps .
- 谁导入了它：codemap --importers <file>
- 受影响范围：codemap blast-radius
扫描范围：仅 src/ 与 packages/，排除 vendor/、dist/
```

## 四、怎么读结果：覆盖率状态

依赖类回答**必须看覆盖率状态**，不然会把「没查到」当「没有」：

| 状态 | 含义 | 怎么办 |
|---|---|---|
| `complete` | 全仓扫完 | 可当依据 |
| `partial` | 只扫了一部分 | **当「分析不完整」处理**，说清扫了多少 |
| `unavailable` | 拿不到 | 回落源码搜索 |

来源状态另有六种：`authoritative` / `mixed` / `fallback` / `timeout` / `unavailable` / `failed`。

**超时或失败返回的是「带来源的空结果」，不是空图**——看到空结果先看来源状态，别直接下结论。

## 五、不可用时怎么办（硬规则）

以下任一情况，**如实报告并回落源码搜索**：

- 工具未安装；
- 实测版本**低于**项目声明的基线；
- 语言不受支持；
- 覆盖率是 `partial` / `unavailable`。

报告写法：**「本仓库代码地图不可用 / 不完整」+ 原因**，然后照旧用源码搜索与既有验证流程。

⛔ **不得报成「检查通过」**，也不得因为缺少工具就停下所有任务。

**版本不一致时**：低于基线一律按「分析不完整」处理——这样多版本并存不会变成「有人以为查全了」。基线升级由项目自己重跑采用动作更新那一行，中央不推送。

## 六、什么时候不用它

- **纯文档改动**、明确不涉及代码依赖的任务：不必查，但要说明「本次未查图」；
- **小仓、单模块局部改动**：扫描成本可能大于收益，判断权在 agent；
- **需求还没成形时**（第 1、2 步）：此时查图先于需求，是浪费。

## 七、怎么关掉

项目在自己的 `AGENTS.md` 写一句：

```text
本仓不适用代码地图
```

主文件认这一句即关闭。**关闭不等于「不合格」**——小仓、文档仓关掉是正常选择。
