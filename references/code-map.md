# 代码地图：就绪、使用与诚实回落

> 本文件是主流程的动作细则，不是选修：动笔前查图、判断就绪 / 不可用 / 跳过、交付影响对账时必须读。压缩后不可见或版本变了时重读。
> 项目接入和显式配置走 [应用到项目](apply-to-project.md) 的共用检查与 §六；普通任务不补制度或未授权配置。
> 依据：`rationale.md` R24、R25、R26。地图仍按 R24 试用；真实仓报告与最小复现的证据边界见 R26。

## 一、能回答什么

结构、静态依赖、谁导入某个文件、实际 diff 可能影响谁，用于确定改动面和验证线索；不是测试或审核的替代品。

静态 import 之外的事件、数据库约定、运行时注入、跨服务契约、反射和动态加载不能靠图排除。「没发现」不等于「没有」，工具未提供的覆盖证据不能由 agent 补成成功；发现范围外影响先报告，不自动夹带修复。

## 二、安装与查询副作用

推荐工具 `codemap`。已核 4.6.0 的 Homebrew 入口为 `JordanCoin/tap` 的 `codemap`，依赖含 `ast-grep`；**机器安装单独获准后**才运行：

```bash
brew tap JordanCoin/tap
brew install codemap
```

以上不是固定安装 4.6.0 的承诺；实际安装版本必须重验。换机器或独立 clone 的工具和配置不假定已就绪。

**不在项目装二进制，不默认跑 `codemap setup`**。一手 README 的 setup 会写 `.codemap/config.json`、`.claude/settings.local.json`、`.codex/hooks.json`、`.mcp.json`、`.codex/config.toml`；hooks 读会话 daemon 状态，`watch start` 另启后台 daemon。setup、Hook、MCP、daemon、新脚本均须 [可执行资产升级闸](apply-to-project.md)，配置请求不授权这些，也不授权 brew 安装。

**不跑 setup 不等于无写入**：4.6.0 在无配置 Git 假仓普通查询会自动生成 `.codemap/config.json` 并可能向 `.git/info/exclude` 加 `.codemap/`，工作区仍可干净。先只读核持久授权、配置选择和版本，不先扫描试副作用。

写入许可须从项目地图短入口可核：用户来源、允许的具体文件 / Git 元数据、用途、触发条件及主检出 / 未来 linked worktree 的作用域；未明确覆盖其他工作区或共享 `.git` 的写入就不做，回落源码。版本、命令、路径、范围或作用域改变时重核许可，文档提过副作用不等于批准。

一手依据（固定源码，不把 issue 当事实）：[自动配置与 Git 排除](https://github.com/JordanCoin/codemap/blob/1fae668045f5ea9d5fa87035b3e175ee63175bb1/cmd/config.go)、[配置字段](https://github.com/JordanCoin/codemap/blob/1fae668045f5ea9d5fa87035b3e175ee63175bb1/config/config.go)、[工作区与共享配置选择](https://github.com/JordanCoin/codemap/blob/1fae668045f5ea9d5fa87035b3e175ee63175bb1/internal/projectpath/path.go)。未取证的缓存行为不作断言。

## 三、项目入口、范围与多工作区

项目短入口保留四要素：**工具、已验版本基线、四类实际命令、扫描范围**，以及 §二 的具体持久授权、§四 核对得出的**已知盲区与验证证据**。采用动作和模板在 [应用到项目 §六](apply-to-project.md)。

范围必须能从版控恢复：用入口中的明确参数，或只含非敏感策略的版控配置。`.codemap/config.json` 支持 `only`、`exclude` 等字段，但 `only` 是扩展名过滤，**不等于只扫描某些目录**；不得写「只扫 src/ 与 packages/」却实际查全仓。命令不支持某参数时核真实配置路径，不造假参数。

**扫描过滤与语言解析分开核**：相关子项目的分析根、`tsconfig` / `jsconfig` 路径别名、`go.mod` 等解析配置要与源码对应；扫到了文件不等于读到了其配置。多项目仓不能默认仓根的一份配置覆盖所有子项目（依据：rationale R26）。

4.6.0 命令语法示例（占位符须替换，flags 在 path 前；分析根可为已验证的仓根或子项目根，目标文件相对该分析根）：

```text
codemap --json <已验证的分析根>
codemap --json --deps <已验证的分析根>
codemap --json --importers <目标文件> <已验证的分析根>
codemap blast-radius --json --ref <真实交付基准> <实际工作区 Git 根>
```

四类命令逐一验证其分析根、实际读取的参数 / 配置与获批范围一致；临时附加过滤、配置解析警告、自动探测变化都不能静默改变边界。结构视图与单目标输出可不同，实际分析边界必须说清。只纳入获准的精确配置文件，不把缓存、日志、凭据或整个忽略目录强加进 Git。

子项目依赖 / 导入方查询仅作补充；跨项目调用方仍在获批范围内检索，交付 diff 仍从当前工作区 Git 根按真实基准核对，不把缩小后的图拼成「全仓已覆盖」。`blast-radius` 须单独与 Git 变更文件对账，不能因 `--importers` 在子项目根有效就把影响查询也搬过去。更换分析根先按 §二 重核范围及写入许可，未获准则回落源码。

**配置不等于运行状态**：4.6.0 标准 linked worktree 在主检出已有 `.codemap/` 配置时，可复用主配置并分析当前工作区代码；以 `codemap config show <工作区>` 的实际路径及查询 root 核对，不要求每个工作区复制配置。共享配置路径与各工作区运行状态分别核授权；显式 `--setup-root` 会改变选择与状态位置，不默认使用。

接入验证至少分别核主检出有配置、主检出无配置且临时工作区首次配置、独立 clone；新机器另核工具。删除临时工作区后范围仍须由版控恢复，不能依赖即将删除的忽略文件。

派生配置丢失，仅在项目已明确授权且已验证重建约定时复现；否则报告未就绪并回落。此例外不授权普通任务补制度入口、权威范围或新策略。独立 clone 的配置缺失不自动继承本机其他 clone 的许可。

## 四、读结果不能只看 complete

查询先核：`pwd` / Git 根对应自己的工作区，当前代码状态、实际扫描范围、目标及交付 diff 基准。影响查询显式对应真实 PR 基准，不在 master、其他 PR 或不同 worktree 上盲用默认 main。

| 覆盖率 | 可证明什么 | 处理 |
|---|---|---|
| `complete` | 工具声明自己的统计范围扫完 | 仍核目标、范围、分母、实际引用及 diff |
| `partial` | 分析不全 | 报扫了什么，相关部分回落源码 |
| `unavailable` | 拿不到覆盖证据 | 回落源码 |

另核来源状态 `authoritative` / `mixed` / `fallback` / `timeout` / `unavailable` / `failed`、目标 `not_indexed`、缺目标、排除项、截断、文件数与 diff 遗漏。超时或失败可能返回带来源的空结果，不是无依赖的空图。

**分母与实际引用都要核，不能等工具主动报盲区**（依据：rationale R26）：

- 读清 `project-relative` 等限定词实际计入哪些引用；结合解析配置与样本，核别名、包引用、生成代码和排除项是否进入统计。未进入分母不算通过，分母不明就标未验证；不能把局部解析成功率当全仓覆盖率，也不能仅凭字段名称断定所有别名都被排除。
- 接入 / 显式升级时，在拟启用的依赖类查询范围内，按实际存在的子项目配置和引用方式选有已知调用方的样本，与源码交叉核对。不固定要求 Java / Go / TS 各一个，不用没有已知调用方的空样本证明解析正常。普通任务先读既有证据；目标涉及盲区、未验方式、版本 / 配置 / 范围变化，或要据图断言「无人调用 / 影响仅限这些文件」时，针对当前目标补核；无查询许可则直接回落。
- 用源码搜索定位后读上下文，核对**实际引用文件集合**，不能只比数量，也不把文本命中数当真值。Java 等符号引用要查简单类名、通配符及同包使用；Go 区分包导入与文件内符号使用；TS 核对别名映射与跨项目引用。排除注释、字符串和同名符号误命中，必要时用项目已有解析工具补证。
- 不一致即把受影响的查询 / 范围标为不完整，保留已发现的依赖作线索，相关部分回落源码。抽查一致只证明所查样本，未查部分仍未验证；不据此解禁全仓依赖结论。结构查询可在自身范围已核时继续使用，不因一类依赖盲区停全部任务。

**complete 也可能漏目标、漏引用或漏 diff**。未索引、范围不符、已知调用方缺失、漏新文件、不完整 diff 或输出截断均不能读成「无影响 / 检查通过」；`No Changes` 也须与 Git 实际变更相符。相关部分回落源码，用 `git diff`、`git status` 和直接检索补证。图不能替代非静态契约、测试和审核。

## 五、就绪不满足时

以下任一条件，报告「本仓代码地图不可用 / 不完整 / 未验证」及具体原因，并回落源码：

- 工具缺失、语言不支持；
- 实测版本低于项目基线；
- 版本高于已验基线但本项目尚未验证兼容性：只读报告差异、回落，不拿新版查询作通过；显式升级时在假仓验证契约与副作用后更新基线；
- 覆盖不完整、目标未覆盖、分母不明、引用核对不符、解析配置不匹配、来源诊断不可信、范围 / 工作区 / diff 不符；
- 配置缺失 / 解析失败 / 范围不可恢复，或查询写入未获准。

**不能伪报通过，也不单因地图缺失停全部任务**；回落不足以支撑关键范围时才停受影响部分。普通任务不安装、不开 setup、不补配置、不改共享 Git 元数据、不顺手升级项目入口。

本次命令、工作区、基准、相关发现及限制放现有需求 / PR 验收证据，不提交整图、不维护手工影响总台账。接入 / 显式升级时把已知盲区、验证过的子项目 / 引用方式、分析根与解析配置、样本核对结果、版本 / 日期及证据链接写进项目短入口；未验项明确写「未验证」。普通任务的新发现只进当次证据，入口持久更新仍交显式升级；旧入口没写盲区不等于没有盲区。

## 六、合理跳过

- 纯文档、不涉及代码依赖，或项目声明不适用时，如实写「本次未查图」与原因。
- 小仓、单模块局部任务扫描无净收益，可合理跳过并说明；不是固定扫描打卡，也不判项目不合格。
- 需求未成形时不先于需求扫图；调查适用且就绪后两段都用，不由审核档位决定是否查清影响。

spec-flow 本仓主要是 Markdown，图增量低；本次修改以引用检索和检查脚本测试核影响，不在本仓运行地图。本提示仅说明本次边界，不作为可追加项目名单。

## 七、关闭与效力

项目 `AGENTS.md` 可写「本仓不适用代码地图」，主文件认这一句；关闭不等于不合格。

本文件随主流程生效，无选修修饰词；只有**配置 / 接入**须显式发起。执行细则不是第二份常驻入口，使用当刻读；历史采纳解释不增义务。机械检查只验文件 / 路径 / 结构，不证明自然语言入口和工具行为永久正确。
