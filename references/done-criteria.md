## 一、完成标准 = 有限承诺

约定功能实现，相关正常 / 异常 / 边界 / 回归测试通过，无未处理的已知阻断缺陷，证据齐全。

**「没有 bug」按这一句读**——它不是「保证以后永不出错」，而是「这次约定的功能做到了、测过的都过了、已知阻断项清零、证据在」。这条口径用来挡住两头的歪读：

- 往松读：「没测过 = 没问题」——不行，缺的就是缺的；
- 往紧读：「上线后可能出的问题也算没完成」——不行，那是观察式收尾管的事（见下节）。

## 二、观察式收尾默认不进单

「上线后观察 N 天」「等真实用户用后确认稳定」「持续跑一段时间看有没有波动」这类**默认不写进验收项、不当关单条件，也不自动开一张观察单**。

要留线索的，在开单时记一句「不在本单验收」＋何时核对。上线后真出了问题，照旧开 bug 单挂链接——这是一条正常的路，不是流程失败。

**为什么默认禁**：这类条目的通过判据是「没出事」，而「没出事」永远为真直到出事为止。收进验收项会把 issue 无限期挂着，同时让「完成」失去可判定的含义。

## 三、例外须方案期批准

上面的默认有例外，但**例外只在方案期批**，实施期不能自己给自己放行。

### 三类例外（正文保留的枚举）

| # | 例外类型 | 说明 |
|---|---|---|
| 1 | **真实时间** | 结论本身依赖时间流逝，模拟时间替代不了（如证书轮转跨周期） |
| 2 | **合规要求** | 外部合规 / 审计明确要求一段观察期或留存期 |
| 3 | **必要的持续负载测试** | 结论依赖长时段真实负载，数据回放或压测替代不了 |

三类之外的都不算例外。拿不准时不自判，摆例外卡让用户定。

### 例外卡（方案期、第 2/3 步）

写明四件事，缺一项不算批过：

1. **验什么** —— 具体看什么信号、什么算异常；
2. **为何替代不了** —— 为什么模拟时间 / 数据回放 / 压测做不到；
3. **多久结束** —— 明确的截止时间，不写「看情况」；
4. **怎样算通过** —— 可判定的通过判据。

### 纳入之后

- 纳入的例外**挡关单**——直到出结论（通过或失败）才关；
- 到截止时间仍无结论的，按「未通过」处理并如实报，不默认顺延；
- 例外只在**方案期**批准：实施期新冒出的观察式需求，要么走正常验收、要么另开单，不回头补批。

## 四、与长尾验收的分工

- **本单**：交付约定功能 + 可判定的验收证据。
- **长尾**：不在本单验收的观察项，按第二节留一句线索；上线后的问题照开 bug 单。
- **不做的事**：不为长尾另开一张「持续观察」单，不把观察期写成关单条件。
