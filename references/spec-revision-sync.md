# 修订 spec：全文同步所有落点（第 5 步修订时读）

> 主文件 `SKILL.md` 只留核心句；本文件是展开，走到这一步时读。

改一条「判据 / 定义 / 常量 / 术语」时，不是改完那一句就完了——它一定在别处有回响。**必须全文搜它的所有落点，逐一同步：**

| 落点 | 是什么 |
|---|---|
| 机制 / 原理节 | 「怎么判、为什么这么判」的正文 |
| 实现 / 数据源节 | 用哪个键、哪份产物、哪个脚本 |
| 实施步骤 | 要不要新建脚本/组件、谁做 |
| 验收标准 | 有没有对应的可验项（**没有 = 这条判据没进验收，等于没落**） |
| 跨文档引用 | 父文档、「唯一 owner」文档、兄弟 spec |
| 历史记录节 | 旧裁决与新裁决打架时，旧的要标「已被取代」 |

**最容易漏的三个**：① 父文档（改了子 spec、忘了几百行外的总纲）；② 唯一 owner 文档（改了成员/口径、忘了那个自称 owner 的）；③ 落地物（spec 里写了、脚本/代码里其实没有——这种"文档有、实物无"要单独标出来）。

**改表格**：markdown 单元格不支持换行（要 `<br>`）——把长内容塞进单元格会把整张表写断。改完数一遍每行未转义的管道数，与表头不一致的就是写坏了。

**改章节编号**：先 `grep` 谁引了这个号（代码注释、别的文档）——编号一动，锚点全废。

为什么有这条：只改判据那一句、别处不同步，照 spec 施工等于白改（依据：rationale R1）。
